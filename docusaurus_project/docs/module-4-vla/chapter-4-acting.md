# Chapter 4: Acting: Executing Behaviors

With perception and planning in place, the final step in a Vision-Language-Action (VLA) system is **acting** – translating the robot's plan into physical movements and interactions with the real (or simulated) world. This chapter focuses on connecting the VLA planning output to ROS 2 actions.

## Connecting LLM → ROS Actions

The sub-tasks generated by our language model (LLM) need to be mapped to concrete robotic actions. This mapping can be:
-   **Direct Mapping**: A sub-task like `grasp_red_cube` directly triggers a pre-defined ROS 2 action (e.g., a `GraspObject` action server).
-   **Parameterization**: The LLM might output parameters for an action (e.g., `navigate_to_pose(x=1.0, y=0.5)`).
-   **Orchestration**: A central "robot executive" node might receive the LLM's plan and orchestrate a sequence of ROS 2 actions.

## Safety and Correction Loops

Executing actions in the real world carries inherent risks. VLA systems need robust safety mechanisms:
-   **Collision Avoidance**: Ensuring planned movements avoid obstacles.
-   **Force/Torque Limits**: Preventing the robot from exerting excessive force.
-   **Human-in-the-Loop**: Allowing human oversight and intervention.
-   **Error Recovery**: Strategies for dealing with failed actions (e.g., if a grasp fails, retry or ask for help).

These are often implemented as feedback loops, where sensor data continuously monitors the execution and triggers corrective actions if deviations occur.

## Exercise: Robot Picks an Object Using VLA Plan

Let's simulate a robot executing a sub-task generated by our VLA planner, specifically "grasp_red_cube". We'll create a script that conceptually maps this sub-task to a ROS 2 action.

### Step 1: Assume an Action Server Exists

For this exercise, assume there's a ROS 2 action server running (e.g., `grasp_object_server`) that takes a `GraspObject.action` goal. The goal would typically include information about the object to grasp (e.g., its pose, dimensions).

### Step 2: Create a Python Script for Action Execution

This script will take a specific sub-task (like `grasp_red_cube`) and send the corresponding goal to the (conceptual) ROS 2 action server.

```python
# action_execution_script.py
import rclpy
from rclpy.action import ActionClient
from rclpy.node import Node
from action_msgs.msg import GoalStatus # For status codes

# Conceptual GraspObject Action (similar to NavigateToPoseAction from Module 1)
class GraspObjectAction:
    class Goal:
        def __init__(self, object_name="", object_pose=None):
            self.object_name = object_name
            self.object_pose = object_pose # Example: geometry_msgs/Pose
    class Result:
        def __init__(self, success=False):
            self.success = success
    class Feedback:
        def __init__(self, progress_percentage=0):
            self.progress_percentage = progress_percentage


class GraspActionClient(Node):

    def __init__(self):
        super().__init__('grasp_action_client')
        self._action_client = ActionClient(
            self,
            GraspObjectAction, # Use our conceptual action
            'grasp_object')

    def send_grasp_goal(self, object_name):
        goal_msg = GraspObjectAction.Goal(object_name=object_name)

        self._action_client.wait_for_server()

        self.get_logger().info(f'Sending grasp goal for: {object_name}')

        self._send_goal_future = self._action_client.send_goal_async(
            goal_msg,
            feedback_callback=self.feedback_callback)

        self._send_goal_future.add_done_callback(self.goal_response_callback)

    def goal_response_callback(self, future):
        goal_handle = future.result()
        if not goal_handle.accepted:
            self.get_logger().info('Grasp goal rejected :(')
            return

        self.get_logger().info('Grasp goal accepted :)')

        self._get_result_future = goal_handle.get_result_async()
        self._get_result_future.add_done_callback(self.get_result_callback)

    def get_result_callback(self, future):
        result = future.result().result
        status = future.result().status
        if status == GoalStatus.STATUS_SUCCEEDED:
            self.get_logger().info(f'Grasp succeeded! Result: {result.success}')
        else:
            self.get_logger().info(f'Grasp failed with status: {status}')
        rclpy.shutdown()

    def feedback_callback(self, feedback_msg):
        feedback = feedback_msg.feedback
        self.get_logger().info(f'Received feedback: Progress {feedback.progress_percentage}%')


def main(args=None):
    rclpy.init(args=args)
    action_client = GraspActionClient()
    
    # Simulate receiving a sub-task from the VLA planner
    sub_task = "grasp_red_cube" 
    
    if "grasp_" in sub_task:
        object_to_grasp = sub_task.replace("grasp_", "")
        action_client.send_grasp_goal(object_to_grasp)
    else:
        action_client.get_logger().info(f"Unknown sub-task: {sub_task}")
        rclpy.shutdown()

    rclpy.spin(action_client)


if __name__ == '__main__':
    main()
```

